# 00 · 先规定什么算“知道了”

[English](en/00-evidence-and-scope.md)

## 证据等级

| 等级 | 可以说什么 | 不可以顺便声称什么 |
|---|---|---|
| 文件证据 | 某归档/脚本有某名称、分支或配置 | 该路径此刻一定执行 |
| 静态原生证据 | 本构建某函数读取/写入某字段 | 该字段在所有上下文含义相同 |
| 运行时只读证据 | 当前对象/调用点出现了某值 | 改它一定安全、是因果根源 |
| 单变量实验 | 指定条件下某改动带来可复现差异 | 其他模式/角色也成立 |
| 用户游玩验证 | 用户确认了具体操作结果 | 所有回合、重赛和收尾已覆盖 |
| 集成/发布验证 | 新打包环境和集成版本通过指定检查 | 单元测试等于完整游戏兼容性 |

本文将已实测结果、源码推断、候选和未知分开。历史文档的“待测”可能早于后来的用户成功；反过来，一个功能早期成功，也不能覆盖后来新增的全部模块。

## 证据写法

每个结论至少交代：构建哈希、数据来源类型、模式与双方角色、读取时机、操作、观测、限制、下一步反证。公开时只保留复现所需的字段，删除进程绝对地址、参与者标识和本机路径。

例：“本构建自由训练P1奥莉，在原生输入入口同步基础及派生按钮后，指令栏和实际轻攻击都出现。”比“写A成功了”更有用。前者区分了显示与执行，并说明了位置。

## 本项目最重要的反例

- 选角格可见，不代表确认后加载同一个角色。
- 指令栏显示A，不代表实际攻击逻辑收到了完整按钮状态。
- Flag回读成功，不代表完整Boss行为已移植。
- CPU预测分支里出现ThrowTech，不代表真实对局已经拆投。
- `.foit`含有状态名，不代表动画帧/子对象/结束路径完整。
- 进程地址可读可写，不代表对象仍属于本场、仍是同一代对象。
- 文件解析成功，不代表采集数据可训练或模型可实战。
- 内置播放成功，不代表自写输入执行器已经复现它。

## 范围

研究以自己持有的游戏资源、公开工具源码和用户授权的离线实验为基础。没有完整重建引擎源码、所有模式入口、全部FOIT指令、全角色帧表或网络协议。禁止用“基本很久没更新”代替哈希检查。

公开文档的证据出处见[SOURCES.md](../SOURCES.md)。不可公开的原始记录只用脱敏汇总结论表达，不伪造可供公众下载的证据链接。
