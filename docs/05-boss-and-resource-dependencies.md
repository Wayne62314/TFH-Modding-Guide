# 05 · Boss不是一个开关：角色、阶段、资源和收尾

[English](en/05-boss-and-resource-dependencies.md)

## 将“Boss可玩”拆成四件事

1. 标志增强：某Flag切到角色既有增强分支。
2. 动作入口：玩家有办法进入某个Boss状态。
3. 场景控制：飞行、镜头、风、障碍、召唤和阶段转换等配套。
4. 完整战斗闭环：资源、伤害、退出、受击、重赛和正常控制全部合理。

只完成第一项，应叫“增强/标志实验”，不是完整Boss。只强制进入状态，也不能把剧情控制系统算作已经移植。

## 奥莉：Flag27、三阶段与Book

基础增强通过已确认的角色标志位布局，在角色初始化完成后设置Flag27。位回读能证明写入，但不能单独证明所有隐藏招式已开放。

三阶段则依赖Flight_Start、Flight_N_BG、HomingSparkCast等状态，以及玩家输入接受、空间移动与子对象。早期WASD只让Book移动、本体不动，揭示“角色”不是一对x/y字段；需要沿原剧情的角色位置同步方法，核对本体、Book、实际位置/缓存位置和镜头关系。

教程沙盒先保留原Free Play初始化，不挂原Boss自动AI，避免它覆盖玩家操作。普通对战接入再从Lua绑定包装定位可用的原生状态排队、输入和同步路径。不能把沙盒成功直接等同于所有本地模式都完成。

## Fred与漩涡

Boss Fred需要可用状态、资源、所属角色、场景内依赖和退出路径。有的流程依赖碰撞/半实体槽位；原剧情还有地图/阶段安排。普通场地的控制器必须补足最小必要依赖，而不是直接加载完整Boss地图造成模式混乱。

已采用的工程办法包括：召唤排队、冷却、等待Intro退出、只找P1实际拥有的Fred、拒绝多个模糊对象、收尾时重新确认代数、先子后父清理。不能只搜名字为FredBoss的第一个对象，更不能直接把Frida分配的内存交给游戏的free。

“漩涡后发红、无法再放技能”说明状态、输入接受或效果恢复可能留在中间态。修复要沿原生结束流程恢复，不是每帧写Stand/重建角色。历史对手暂时显示Arizona的报告未稳定复现，不能宣称根因已完全查清。

## 天火Backdraft与Baihe借用

旧天火AI保留地面/空中Backdraft线索；Baihe也有同名状态与相关图集引用。部分旧注册/决策调用被注释，名称存在不代表默认启用。

地面A/B/C攻击效果经过用户验证，击飞距离有区别，但本体动画/特效缺失；借用Baihe相关状态也出现角色消失或无动画。结论应是“攻击逻辑可达，但表现依赖不完整”，而不是“完整Boss已恢复”。

同名状态的动画/资源索引可能只在自己的角色数据中有意义。搬状态名、状态指针或让另一角色进入它，都不能自动解决图集、子弹、音效、父对象、输入和销毁关系。需要逐层核对状态体、可见性、帧引用和依赖，不能由历史复用传闻推出整套资产可互换。

## 普通Fred跨角色与Supernova

天火召唤普通Fred的实验要求P2为普通奥莉，让游戏正常加载依赖，再创建/调用相关对象。这是诊断用的“资源供体”条件，不是所有对手都可用，也不是独立预加载已实现。重复召唤还需要原对象确实退出以及冷却恢复。

Baihe二气Supernova对象的最小实验未得到可用法球/完整演出；UI保持禁用。**失败也是必须公开的开发信息**：只有对象名称和一次创建尝试，不足以承诺伤害、两格气消耗和完整大招。

## Velvet / Paprika

Velvet的Boss_Install、Boss_Wind_Idle、Boss_IceL/M/H等状态可用作实验入口；剧情风推另由Lua持续施加，所以龙卷风状态不包含全套风场。退出/隐藏/清理仍有依赖，原公开工具明确要求使用后重启。

Paprika剧情阶段会设置Flag27，但前景跃击/传送还受行为树和舞台流程影响。标志实验用户确认可运行，实际强化效果不清楚；没有据此宣称完整前景Boss攻击已开放。

这些模块独立实验与集成UI的验证等级可能不同。公开源码S1是接口/防护参考，不是全Boss复刻保证。
