# 11 · 工程、测试、发布和公开资料的边界

## 两条修改路线分别回滚

**资源补丁**：游戏关闭时备份目标包，记录安装前/候选/安装后哈希；只改必要条目，未改内容逐字节比较。遇到未知后续修改拒绝覆盖。多个补丁按安装依赖逆序卸载，不能随便拿最早备份覆盖后来改动。

**运行时工具**：哈希/签名验证后安装钩子，场景/角色/线程/代数检查，限时和人工停止。卸载钩子不等于撤销所有玩法效果；菜单需说明关闭开关何时应用，必要时要求重新加载或重启。

## 模式白名单的正确描述

历史代码有过“0..14排除1/11”的宽分类，也有角色工具限定0或训练组合的窄规则。**不是逐模式实测表**。后续名称映射识别11为LEADERBOARD类型，旧注释把它直接叫联网并不准确；保守拒绝可以保留，但文档要纠正语义。

更不能把排除了某个mode数字当成完整联网隔离保证。网络连接、回滚、预测、回放与本地场景的关系尚未全还原。公开发布保持最小已验证范围；联网前关闭并重启。

## 测试矩阵

| 维度 | 最低检查 |
|---|---|
| 包修改 | 索引边界、路径安全、条目对齐、未改条目、恢复哈希 |
| Native接口 | 错版本拒绝、签名、空指针、场景/队伍、代数、退出 |
| 输入 | 原始缓冲不变、派生字段、press/held/release、同时按钮、重复回调 |
| 状态控制 | 起手、等待、受击/中断、超时、重复召唤、销毁及重赛 |
| 模式 | 训练/本地CPU/双人分别验证，未知/联网拒绝 |
| 数据 | 预测排除、同帧pre、输入对齐、分段去重、尾批、整场划分 |
| UI | 异步连接、语言切换、禁用未成功功能、停止及错误提示 |
| 打包 | 新目录、中文/空格路径、缺全局Python/Tk环境、全包解压、自检 |

模拟测试负责覆盖边界，不替代真实游戏。把“单个模块实测”“集成版本回归”“全新机器兼容”分别写在发行说明，不相互冒充。

## GUI和可分享包

我们把Python连接/日志与JS玩法钩子分开，界面异步工作，避免主线程等待进程查询。语言切换只改变文字，不应隐式改选项、重新连接或启用功能。F键、U暂停、Y清理等冲突要公开说明。

早期Setup/Start依赖本机Python/Frida，复制到另一目录后就失败；后来用PyInstaller打包Python、Frida、Tcl/Tk等运行依赖。必须保留整个_internal目录，不是只复制EXE，也不是GitHub自动Source code ZIP就可运行。

便携工具应解压到独立可写目录，不必放游戏目录。新版本使用新目录，不混旧文件；保留源码、依赖许可、校验和和故障反馈格式。未签名被警告时，不建议关闭安全软件。

## 性能和恢复也属于验收

不要只验“能变身/能出招”。还要测失焦、暂停、控制权归还、回合结束、反复重赛、按键释放、日志上限和进程关闭。一个功能有效但每帧阻塞很多毫秒，仍不适合发布。

shutdown设计为请求清理→在正确线程/上下文尝试→确认完成或报告pending，不为“立即退出”在错误线程强行销毁游戏对象。

## 发布前隐私/素材清单

只从白名单生成全新公开仓库，不能把私密库删几份文件后直接改可见性。Git历史也可能包含数据。排除凭据、原始录像/昵称/账号、本机路径/进程地址、转储、完整GFS/FOIT/纹理、原包备份和未授权素材。

可公开：自己编写的说明、合成示例、可复核的构建哈希/RVA、经过审查的统计、公开源码链接及失败结论。依赖外部游戏资产的工具应分发补丁/脚本/安装器，而不是整个游戏包。一个仓库公开不自动为第三方素材授权。
